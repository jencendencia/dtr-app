# Fix: "Clear & Re-sync" Should Also Clear Device Attendance Logs

## Problem

On ZKTeco devices, deleting users does NOT delete attendance logs. When the user deletes all users on the device and clicks "Clear & Re-sync":
1. The app clears local DB (teachers + logs) ✓
2. Re-sync pulls orphaned attendance logs from the device
3. Auto-creates "Employee 1", "Employee 2" etc. from those logs

## Solution

Make "Clear & Re-sync" also wipe attendance logs from the physical device before re-syncing.

## Changes

### 1. `src/main/zktecoService.js` — Add `clearAttendanceLog()` method

The `zkteco-js` library already has `device.clearAttendanceLog()`. Wrap it:

```js
async clearAttendanceLog() {
  if (!this.isConnected()) {
    return { success: false, message: 'Not connected to any device.' };
  }
  try {
    await this.device.clearAttendanceLog();
    return { success: true, message: 'Attendance logs cleared from device.' };
  } catch (err) {
    return { success: false, message: `Failed to clear logs: ${err.message}` };
  }
}
```

### 2. `src/main/main.js` — Add `clear-device-data` IPC handler

New handler that clears both device logs AND local DB:

```js
ipcMain.handle('clear-device-data', async () => {
  // 1. Clear attendance logs on the physical device
  const clearLogsResult = await zktecoService.clearAttendanceLog();
  // 2. Clear local DB (reuse clear-device-sync-data logic)
  // ... teachers + logs deletion ...
});
```

### 3. `src/renderer/renderer.js` — Update "Clear & Re-sync" button handler (line 1439)

Replace the current flow to call `clear-device-data` instead of `clear-device-sync-data`:

```
Current:  clear-device-sync-data (DB only) → sync-device-attendance
New:      clear-device-data (device + DB) → sync-device-attendance
```

### Files Modified

| File | Change |
|------|--------|
| `src/main/zktecoService.js` | Add `clearAttendanceLog()` method |
| `src/main/main.js` | Add `clear-device-data` IPC handler |
| `src/renderer/renderer.js` | Change "Clear & Re-sync" to call `clear-device-data` |

### Verification

1. Add users to device → Sync → Teachers created ✓
2. Delete users on device
3. Click "Clear & Re-sync" → Device logs cleared + DB cleared → Re-sync shows 0 records ✓

# Feature: Delete Teacher from Device When Deleted in App

## Problem

The `delete-teacher` handler (main.js:291) only deletes from the local DB. It never calls `zktecoService.deleteUser()` to remove the user from the physical ZKTeco device. So:
- Delete teacher in app → teacher still exists on device
- Next sync → teacher gets re-created (or matched if biometric_id exists)

## Solution

Modify `delete-teacher` to also delete the user from the device when connected.

## Changes

### 1. `src/main/main.js` — Update `delete-teacher` handler (line 291)

Add device deletion after DB deletion:

```js
ipcMain.handle('delete-teacher', async (event, teacherId) => {
  try {
    const teacher = db.prepare('SELECT id, name, biometric_id FROM Teachers WHERE id = ?').get(teacherId);
    if (!teacher) {
      return { success: false, message: 'Teacher not found.' };
    }

    // Delete from device if connected
    if (zktecoService.isConnected()) {
      await zktecoService.deleteUser(teacher.id);
    }

    // Delete from local DB
    db.prepare('DELETE FROM AttendanceLogs WHERE teacher_id = ?').run(teacherId);
    db.prepare('DELETE FROM TeacherTimeSchedule WHERE teacher_id = ?').run(teacherId);
    db.prepare('DELETE FROM Teachers WHERE id = ?').run(teacherId);

    logActivity(currentSessionUser, 'Delete Teacher', `Deleted teacher "${teacher.name}"`);
    return { success: true };
  } catch (err) { ... }
});
```

Note: `deleteUser(uid)` uses the DB row `id` as the device's internal record ID (same as how `setUser` enrolls with `teacher.id` as `uid`).

### File Modified

| File | Change |
|------|--------|
| `src/main/main.js` | Add `zktecoService.deleteUser(teacher.id)` call in `delete-teacher` handler |

### Verification

1. Add teacher → Enroll to device → Teacher exists on device ✓
2. Delete teacher in app → Check device users → Teacher removed from device ✓
3. Sync after deletion → No orphaned records ✓

## Problem

The Edit modal already supports creating new logs for empty slots, but days without logs don't appear in the table at all — there's nothing to click "Edit" on.

## Root Cause

In `renderer.js:2213`:

# Feature: Resize DTR to 3/4 and Center

## Problem

In the Print DTR tab, the DTR form fills the entire page width. The user wants it at 75% of its current size and centered.

## Root Cause

- Screen: `.dtr-printable-area` has no width constraint, so it stretches to fill its container.
- Print: `.dtr-printable-area` is set to `width: 195mm` (nearly full A4 width).

## Solution

1. Screen view: Add `max-width: 75%` and `margin: 0 auto` to `.dtr-printable-area`
2. Print view: Reduce width from `195mm` to `146mm` (75% of 195mm), height from `275mm` to `206mm`

## Changes

### `src/renderer/dtrForm.css`

**a) Screen styles (line 216):**
```css
.dtr-printable-area {
  font-family: "Times New Roman", Times, serif;
  color: #000;
  box-sizing: border-box;
  max-width: 75%;
  margin: 0 auto;
}
```

**b) Print styles (line 44):**
```css
.dtr-printable-area {
  width: 146mm !important;
  height: 206mm !important;
  margin: 0 auto !important;
  padding: 5mm 10mm !important;
  ...
}
```

### File Modified

| File | Change |
|------|--------|
| `src/renderer/dtrForm.css` | Add `max-width:75%;margin:0 auto` for screen; reduce width/height in print media |

### Verification

1. Generate DTR → DTR displays at 75% width, centered on screen ✓
2. Print DTR → Output is 75% of page, centered ✓
5. Existing days with logs still work correctly ✓
